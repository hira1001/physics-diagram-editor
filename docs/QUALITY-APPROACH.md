# 品質の進め方（319 マトリクスとの関係）

## 方針

[`QUALITY-TEST-MATRIX.md`](./QUALITY-TEST-MATRIX.md) の 319 件は **要件の網羅リスト・トレーサビリティ辞書** として保持する。  
**「319 件すべて合格するまでリリースしない」** という運用は **採用しない**。

代わりに [`PRODUCT-ALIGNMENT.md`](./PRODUCT-ALIGNMENT.md) §5 の **シナリオ + 単体 + P0 E2E** を日々のゲートとする。

## 毎変更のゲート

```bash
npm run typecheck
npm run test:unit
# 必要に応じて npm run test:e2e（代表シナリオ）
```

## シナリオ（拡張してよい）

| ID | 領域 | 概要 |
|----|------|------|
| SC-MECH-01 | 力学 | テンプレ（斜面）→ 物体 → 力を全部 → 出力 |
| SC-STRUCT-01 | 構造 | 単純梁テンプレ → 構造部品が存在 → 出力 |

新シナリオを足したら `e2e/` にテストを追加し、本表に1行追記する。

## マトリクスを触るタイミング

- P0 回帰で既に ID がある領域を **意図的に変更** したときだけ、該当行の状態を更新する。
- 未実施のまま残る行は **技術的負債のバックログ** とみなし、完了率 KPI にはしない。

## 記録

手動・一括試験のログは引き続き [`TEST-RESULTS.md`](./TEST-RESULTS.md) に残してよい（任意）。
