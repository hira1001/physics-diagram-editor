# 物理図エディタ 品質テストマトリクス

## 1. 目的

本書は、物理図エディタについて合意した要件を、実行可能かつ判定可能なテストへ変換した品質基準である。機能が「存在する」だけでなく、PPTより速く、教科書品質の図を安定して作成・編集・出力できることを保証する。

現在報告されている「力ベクトルが物体の背面へ入り見えない」不具合は `VIS-001` としてP0回帰項目に登録する。修正完了は、この表の合格条件を満たした時点とする。

## 2. 判定規則

| 項目 | 定義 |
|---|---|
| 優先度 P0 | 基本作図、データ保持、出力、視認性を壊す。1件でも失敗ならリリース不可 |
| 優先度 P1 | 標準ワークフローまたは生産性を損なう。初回製品版は全件合格必須 |
| 優先度 P2 | 高度機能、補助機能、長期品質。対象リリースに含める場合は全件合格必須 |
| 自動 | Unit / Component / E2E / Visual Regression / Export解析で判定 |
| 半自動 | 操作は自動化し、見た目・外部アプリ互換などを人が最終判定 |
| 手動 | ユーザビリティ、実機PowerPointなど人による判定が必要 |
| 状態 | `未実施` / `合格` / `不合格` / `対象外（根拠必須）` のいずれか |

### リリースゲート

1. P0とP1が100%合格し、未実施・不合格・根拠のない対象外がない。
2. Chromium系、Safari/WebKit相当、Firefox相当のローカルE2Eが合格する。
3. 1280×720、1440×900、1920×1080、2560×1600で重大なレイアウト崩れがない。
4. ブラウザコンソールの未処理例外、React警告、ネットワーク失敗が0件である。
5. Visual Regressionの差分が承認済みであり、描画要素の重なり・欠落がない。
6. SVG、PNG、PDF、PPTXの出力検査に合格する。
7. 100〜200部品の性能試験と、保存復元・履歴・破損データ復旧試験に合格する。
8. `npm run lint`、型検査、Unit/Component、E2E、production buildがすべて成功する。

## 4. 描画レイヤー仕様

キャンバス上の意味的な前後関係を次の順で固定する。数値が大きいほど前面とする。

| レイヤー | 内容 | 要件 |
|---:|---|---|
| 0 | 用紙、グリッド | 図形を妨げない |
| 10 | 補助線、推論線、ゴースト | 薄く、確定図形と区別できる |
| 20 | 床、壁、斜面、軌道、接続線 | 物体の構造を形成する |
| 30 | 物体、支点、滑車、ばね等の本体 | 前景部品の基準になる |
| 40 | 力、速度、加速度、モーメント等のベクトル | 物体本体より前面。軸・矢尻を欠落させない |
| 50 | `m`、`θ`、`mg`、`N`、`f`等の図中ラベル | 対応図形より前面で可読 |
| 60 | 選択枠、ハンドル | 図中ラベルを恒常的に隠さない |
| 70 | 数値HUD、補完、メニュー | 対象を避けて配置し、閉じられる |

### 標準部品カタログの網羅基準

部品は見た目だけの図形ではなく、接触・接続・運動・変量候補を持つ物理オブジェクトとして扱う。少なくとも次を標準部品としてテスト対象にする。

| 分類 | 標準部品・派生 | 必須の物理的意味 |
|---|---|---|
| 物体 | 質点、直方体、球、円板、円柱、くさび、台車 | 質量、重心、接触点、並進/回転候補 |
| 接触面 | 滑らかな床、粗い床、滑らかな壁、粗い壁、滑らかな斜面、粗い斜面、天井、段差、角、曲面 | 法線。粗い面だけ摩擦・摩擦係数 `μ` を標準候補にする |
| 支持 | 固定端、ピン支点、ヒンジ、ローラー支点、単純支持、支柱 | 支点反力と許容運動 |
| 接続 | 糸、ロープ、ケーブル、軽い棒、ばね、ダンパー | 端点追従、張力/軸力/弾性力/減衰力 |
| 機械要素 | 固定滑車、動滑車、組合せ滑車、輪軸、回転軸、ベルト/コンベア | 接続経路、同一張力、回転/移動方向 |
| 運動経路 | 直線軌道、円軌道、任意曲線、放物線ガイド | 接線、法線、半径、進行方向 |
| ベクトル | 一般力、重力、垂直抗力、摩擦力、張力、ばね力、抗力、浮力、推力、速度、加速度、運動量 | 作用点、方向、長さ、変量、成分分解 |
| 回転 | モーメント、角速度、角加速度、回転方向 | 回転中心、向き、変量 |
| 注釈 | 座標軸、斜面座標軸、角度弧、長さ寸法、半径、重心、点、補助線、テキスト | 対象参照と追従、ラベル衝突回避 |

## 8. 実行順序

1. `VIS-001`、`SHL-019`、`TPL-001`、`DIR-006`〜`DIR-010`を最初のP0回帰セットとして固定する。
2. P0 Unit/Componentを実行し、状態モデル・履歴・参照整合性を先に保証する。
3. P0ローカルE2Eを3ブラウザ・標準密度で実行する。
4. 代表図10種のVisual Regressionを各解像度・倍率で実行する。
5. 出力形式とPowerPoint実機互換を確認する。
6. P1全件、性能、アクセシビリティ、ユーザビリティを実行する。
7. 不具合修正ごとに対応IDを回帰テストへ追加し、合格証跡を残す。

## 9. テスト証跡の記録形式

各実行結果は次の項目を残す。

| 項目 | 必須内容 |
|---|---|
| Test ID | 本書の一意ID |
| Commit | 検証対象のGit SHA |
| Environment | OS、ブラウザ、画面、UI密度、倍率 |
| Result | 合格/不合格/対象外 |
| Evidence | スクリーンショット、動画、trace、出力ファイル、ログ |
| Defect | 不合格の場合のIssue/修正コミット |
| Executor / Date | 実行者と日時 |

自動テスト名にもTest IDを含め、要件・テストコード・結果を追跡可能にする。
